When a customer or a vendor needs to hand you a credential, asking for it over email or chat leaves a
copy in someone's inbox forever. A secret request gives them a one-time page to paste it into instead.

## When to use this

- Onboarding a customer who has to give you an API key
- A vendor sending over SMTP or database credentials
- Anyone outside your organization who should not need an Infisical account

## Walkthrough

<Steps>
  <Step title="Create the request">
    Go to **Secret Sharing** and open the **Request Secrets** tab, then select **Request Secret**. Give it
    a name you will recognise later, since this is the only label you get in the list.
  </Step>
  <Step title="Choose who can respond">
    **Anyone** lets the recipient respond without signing in, which is the option you want for someone
    outside your organization. **Organization** requires them to be a member.
  </Step>
  <Step title="Send the link">
    Copy the link from the row menu and send it however you normally talk to them. The link only accepts a
    value, so it cannot be used to read anything.
  </Step>
  <Step title="Read the value once it arrives">
    The row changes to **Secret Provided**. Select **Reveal Secret** to read it. For how long the value
    stays available, see [shared secret limits](/documentation/platform/shared-secret-limits).
  </Step>
</Steps>

## What the recipient sees

They land on a page with a single field and your organization's branding if you have set it up. They do
not see anything else about your organization, and they cannot see previous responses.

<Note>
  A secret request holds one value. If you need two credentials from the same person, send two requests so
  that each one can be revoked on its own.
</Note>
