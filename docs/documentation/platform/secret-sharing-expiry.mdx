## Overview

When you share a secret, you pick how long the link stays alive and how many times it can be viewed.
Both limits are enforced server side, so a link stops working even if someone kept the URL.

## Picking an expiry

| You are sharing with | Suggested expiry | Views |
| --- | --- | --- |
| A teammate who is online now | 1 hour | 1 |
| A contractor starting tomorrow | 1 day | 1 |
| A vendor working through a backlog | 7 days | 5 |

Shorter is better. A link that expires before anyone leaks it is the cheapest control you have.

## What happens at expiry

The link returns a "no longer available" page. Nothing is recoverable from it, and the secret itself is
deleted from the share table rather than hidden. Re-share it if the recipient missed the window.

## Common questions

<AccordionGroup>
  <Accordion title="Can I extend a link after sending it?">
    No. Expiry is fixed when the link is created. Create a new share instead, which also gives you a
    fresh view count.
  </Accordion>
  <Accordion title="Does viewing count if the page fails to load?">
    A view is counted when the secret is decrypted and returned, not when the page is requested. A
    failed load does not burn a view.
  </Accordion>
</AccordionGroup>
